● Auto mode lets Claude handle permission prompts automatically — Claude
  checks each tool call for risky actions and prompt injection before 
  executing. Actions Claude identifies as safe are executed, while 
  actions Claude identifies as risky are blocked and Claude may try a 
  different approach. Ideal for long-running tasks. Sessions are 
  slightly more expensive. Claude can make mistakes that allow harmful 
  commands to run, it's recommended to only use in isolated 
  environments. Shift+Tab to change mode.

  Summary

  The branch is bumped from Elasticsearch 9.4.3 to 9.5.5. Nothing is committed;
  the working tree holds the diff (28 modified files plus one new test).

  Most of the port is mechanical: ES renamed the reindex response classes,
  removed two interfaces (RealtimeRequest, pooled SearchHits helpers), added
  abstract methods to XContentGenerator, and changed how put-mapping and
  index-source bytes are exposed. Behaviour is unchanged for all of these, with
  one deliberate nuance: ES no longer converts put-mapping bodies to JSON up
  front, so the audit log and the multi-tenancy mapping interceptor now convert
  using the request's content type (a YAML regression test was added).

  Three ES behaviour changes needed real work:

  1. FLS and field masking were bypassed on ES 9.5. ES now streams the fetch
     phase through a coordination action that stashes the thread context and
     re-applies only captured headers. Search Guard kept the user as a
     transient, so fetch requests reached data nodes without a user and the
     reader wrapper applied no FLS/FM. The action filter now also records user,
     origin and remote address as headers. This is security-relevant and must
     ship with the bump.
  2. The modify-data-stream API can delete backing indices. Search Guard
     requires indices:admin/delete on the backing index in addition to modify on
     the data stream (stricter than X-Pack).
  3. ES can create backing indices for past TSDB timestamps on the write path
     (opt-in setting). The new action is registered and added to the
     create-index action group, mirroring X-Pack.

  Rolling upgrade: safe (no serialization, config or setting changes; the user
  header already travels on every transport request). Decisions to review: items
  2 and 3 above, and the header placement in SearchGuardFilter.
